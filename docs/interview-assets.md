# 面试与简历素材（内容质量平台版）

## 一句话定义项目

这个项目不是一个单点 AI 工具 demo，而是一个面向内容质量与数据服务场景的后端平台项目。我重点展示的是事件接入、案例流转、数据服务、异步治理、稳定性与安全能力，AI 只作为 sidecar 增强模块接入。

## 30 秒讲法

我做了一个内容质量与数据服务平台型项目，用 `Go + Hertz` 搭主服务，用 `Python + FastAPI` 做 AI Copilot sidecar。主链路覆盖内容事件接入、案例生成、审计留痕、异步消费和数据查询；工程上补了幂等、事务 outbox、消费者去重、API 鉴权、限流和 Prometheus 风格指标，体现的是一个后端平台工程项目，而不是一个只会调用大模型的实验仓库。

## 90 秒讲法

这个项目主要对齐的是“AI 工具开发工程师-内容质量与数据服务平台”这类 JD。因为这类岗位其实会同时看三件事：第一，你有没有扎实的后端工程能力；第二，你能不能把复杂内容质量流程服务化；第三，你会不会把 AI 放在正确的位置。

所以我把系统拆成两条链。主链路是后端平台：Gateway 接收内容事件，做鉴权、限流和校验；存储层把案例、幂等记录、outbox 和审计日志写进 MySQL；Worker 负责异步消费和持久化 dedup；查询层对外提供案例查询、审计查询和指标接口。增强链路是 AI Copilot，只负责摘要、解释和辅助分析，不参与主判定。

phase 4 里我重点补了几个和 JD 非常强相关的能力：`X-API-Key` 鉴权、Redis 优先的限流、按案例查询审计轨迹、Prometheus 文本指标、以及 worker 持久化去重。这样讲项目的时候，可以把“后端工程 + 数据服务 + AI 工程化边界”三件事放在一个故事里讲清楚。

## 3 分钟讲法

如果面试官让我展开，我会先讲业务问题。内容质量治理不是单纯做一条规则命中，而是要把事件、证据、规则、案例、运营复盘和数据服务放到一个统一平台里。否则系统会碎在脚本、表格和人工流程里，既不稳定，也不利于复盘。

然后我会讲系统设计。我把主链路设计成：`content event ingest -> idempotent persistence -> transactional outbox -> async worker -> case query / audit query / metrics`。这里我刻意把可靠性和安全能力前置，而不是把它们放成“以后再补”的非核心项。比如接入入口按 `event_id` 做幂等，异步链路使用 outbox，消费者侧按 `event_id` 做持久化 dedup，Gateway 上再加 API key 鉴权和限流，整体更像一个线上服务而不是本地 demo。

最后我会讲 AI 的边界。这个项目虽然有 AI Copilot，但我没有把大模型塞到主判定链路里。原因很简单，内容质量平台要求高可靠、高安全、可审计，所以模型更适合做摘要、解释、相似案例提示这种增强工作，而不是直接决定案例结果。这个边界设计，本身就是我对 AI 工程化的理解。

## 你在项目里承担了什么

- 我负责主链路建模，把事件、证据、案例、审计、异步消费抽象成清晰的模块边界。

- 我负责稳定性与安全增强，包括幂等、outbox、鉴权、限流、消费者 dedup、metrics 和 audit query。

## 面试官高频追问与答法

### 为什么这个项目能体现“AI 工具开发工程师”而不是普通后端？

因为我不是简单加了一个模型接口，而是把 AI 放进一个完整后端平台里：主链路先独立可运行，AI 再以 sidecar 形式接入，并通过接口、回退和审计保证工程可控。

### 为什么不让 AI 直接参与主判定？

内容质量平台要求高可靠、高安全和可审计。如果 AI 直接决定结果，风险会更高。我让它做摘要和解释，是为了提升效率，但核心流程仍由规则和服务逻辑控制。

### 这个项目里最体现后端能力的地方是什么？

我觉得是三点：入口幂等、事务 outbox、消费者持久化 dedup。因为它们直接关系到异步链路是否可靠，而这正是后端平台项目的硬实力部分。

### 这个项目怎么体现“数据服务平台”特征？

我不仅做了接入，还做了案例查询、审计查询和指标出口，也就是把处理能力和数据服务能力一起做出来了。这更接近平台，而不是单次处理服务。

### 你这个项目里设计模式和模块化体现在哪里？

我把 Gateway、Repository、Worker、AI Sidecar 拆成清晰模块，并让鉴权、限流、审计查询、指标导出这些能力以可复用方式挂在主链路上，尽量避免业务逻辑和基础设施逻辑写死在一起。

## 结果表达怎么说

这个项目不是线上业务，不适合虚构业务收益，但可以这样表达：

- 我把它做成了一个可运行、可测试、可扩展、可讲解的后端平台样板。
- 它能完整展示我对后端主链路、数据服务能力和 AI 工程边界的理解。
- 相比单纯的模型 demo，它更能体现平台工程岗位关心的稳定性、安全性和协同能力。
