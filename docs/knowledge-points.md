# Knowledge Points

## 学习顺序

1. 通用基础：Go / Linux / MySQL / Redis / MQ / 服务化
2. 岗位核心：架构设计、可靠性、安全性、数据服务、业务抽象
3. 业务映射：内容质量治理与 AI 增强模块边界

## 能力清单

### 数据基础设施与中间件

- MySQL：索引、事务、慢查询优化
- Redis：缓存策略、热点治理、一致性
- MQ：削峰、重试、死信、补偿、幂等消费
- 事务 outbox：业务写入与消息发布解耦，保证最终一致性

### 后端服务工程能力

- API 设计与分层架构
- 重试、超时、回滚与幂等
- 模块化与可复用服务边界
- 请求幂等键设计与 replay 语义定义

### 服务可靠性与安全性

- 限流、降级、熔断与容量评估
- 鉴权、审计日志、可追踪链路
- 压测、性能分析、告警与监控
- outbox relay 的重试与 dead-letter 策略

### 内容质量与数据服务平台能力

- 内容事件建模：`Event / Rule / Case / Evidence`
- 面向运营和策略的统一数据服务接口
- 误判复盘和规则迭代机制

### 大模型应用工程化

- LLM 服务化接入与结构化输出
- 失败回退策略与可用性兜底
- AI 增强而非替代主链路

## 面试高频问法（对应本仓库）

- 缓存与数据库一致性如何保证？
- MQ 重复消费如何保证幂等？
- 如何做服务拆分并保持可复用？
- 稳定性治理怎么量化收益？
- 内容质量平台为何必须有独立数据服务层？
- AI 功能失败时如何保证系统可用？
